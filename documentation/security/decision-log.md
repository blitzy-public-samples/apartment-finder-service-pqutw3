# Security Remediation Decision Log

This log is the single source of truth for **why** every non-trivial decision in the security
remediation was made. Code comments state only *what* a change defends against and carry a stable
`SEC-NN` identifier; the reasoning lives here, keyed by that identifier. Source code, configuration
files and dependency manifests therefore contain no rationale, and nothing here is duplicated into
them.

**Who reads this.** A security reviewer working through the change set before it ships. Every
judgment call is a row, so the review never has to reconstruct intent from a diff.

**What lives elsewhere.** [`SECURITY.md`](../../SECURITY.md) carries operational secret handling, the
verification commands, the deferred follow-ons and the residual-risk register.
[`traceability-matrix.md`](traceability-matrix.md) maps each finding to its files and each file back
to its findings. This log records reasoning. Neither of those files is restated here.

A decision is non-trivial if a competent engineer could reasonably have chosen differently. Any
deviation from a literal reading of the requirements gets its own row. An unexplained deviation is a
defect.

**Columns.** *Decision* is what was chosen. *Alternatives considered* names the options rejected.
*Rationale* says why the choice won. *Risk / residual gap* states what the choice leaves open — an
empty cell would mean the decision carries no residual, which is rarely true.

**Entry keys.** Rows carry one flat sequence, `DL-01` onward, assigned in the order the decisions
were taken. The sequence is flat on purpose: the implementing work used several colliding local
labels, so no local label is a key here. Where one appears inside a cell it is provenance, not an
address. Section headings carry the `SEC-NN` finding identifiers, and that is how a code marker
resolves.

## 4. Informational observations reconciled from QA

Three observations were raised as informational rather than as defects: no behaviour is wrong, but a
stated value or an assumed exception hierarchy does not match what the pinned closure actually does.
Each is recorded here so the discrepancy is a settled fact rather than a surprise to whoever writes
the next assertion against it. Every value below was measured against the pinned closure on
CPython 3.9.25 on 2026-07-31.

| Decision | Alternatives considered | Rationale | Risk / residual gap |
|---|---|---|---|
| **DL-16** — Read the installed PayPal SDK version from distribution metadata, `importlib.metadata.version("paypalrestsdk")`, and never from the module's `__version__` attribute. | Assert against `paypalrestsdk.__version__`, which is the more obvious of the two surfaces and the one most test authors reach for first. Alternatively pin the SDK to whatever version its `__version__` reports, so that the two agree. | The two surfaces disagree: distribution metadata reports **1.13.3** while `paypalrestsdk.__version__` reports **1.13.1**. The distribution metadata is the value the manifest pin governs and the value the resolver, the audit tool and `pip check` all act on, so it is the only surface an assertion can correctly read. The disagreement is an upstream packaging inconsistency in the published artifact — the maintainers advanced the release version without updating the in-module constant — and is not something this repository can or should correct. Re-pinning to 1.13.1 to force agreement would move the dependency backwards to satisfy a cosmetic mismatch. | An assertion written against `__version__` will fail against a correctly pinned environment, and the failure will look like a wrong pin rather than a wrong assertion. | **DL-17** — Record that `JWKError` and `JWSError` are **not** subclasses of `JWTError`, and defer the fix to the `ALGORITHM` allow-list at the `config.py` checkpoint rather than widening the exception clause here. | Widen `backend/app/core/security.py:69` from `except jwt.JWTError` to catch `JOSEError`, the common ancestor. Alternatively do nothing and leave the observation unrecorded. | The hierarchy is real and measured: `issubclass(JWKError, JWTError)` is **False**, and both classes descend from `JOSEError`.
